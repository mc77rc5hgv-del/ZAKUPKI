# MCP-мост для РТС‑маркет Краснодарского края

Локальный MCP-сервер связывает AI-клиент с разделом запросов `krd-market.rts-tender.ru`. Он работает через постоянный Chromium-профиль, поэтому поддерживает страницы, требующие JavaScript, ручной вход, ЭП и Anti‑DDoS-проверку.

Архитектура и правила расширения описаны в [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## Возможности

- открытие публичного списка и карточек запросов;
- извлечение видимого текста, ссылок и документов;
- скачивание документов в локальную папку;
- снимки экрана и диагностический снимок доступных элементов;
- действия `click`, `fill`, `select` с двойной защитой от случайной записи;
- изоляция навигации: разрешён только домен из `RTS_BASE_URL`;
- постоянный профиль без передачи логина, пароля или сертификата модели.

## Установка

```powershell
npm install
npm run install-browser
npm run build
```

Первый запуск лучше выполнять с `RTS_HEADLESS=false`. В открывшемся окне вручную пройдите Anti‑DDoS, авторизацию и, если потребуется, выберите сертификат электронной подписи.

## Подключение к Codex / MCP-клиенту

```json
{
  "mcpServers": {
    "krd-market-rts": {
      "command": "node",
      "args": ["C:/absolute/path/to/krd-market-rts-mcp/dist/entrypoints/mcp.js"],
      "env": {
        "RTS_HEADLESS": "false",
        "RTS_PROFILE_DIR": "C:/absolute/path/to/private/rts-profile",
        "RTS_DOWNLOAD_DIR": "C:/absolute/path/to/downloads",
        "RTS_ALLOW_WRITES": "false"
      }
    }
  }
}
```

Начните с `rts_session_status`. Если он сообщает `antiDdos: true`, завершите проверку в открытом браузере и вызовите инструмент повторно.

## Безопасность и ограничения

По умолчанию `rts_act` заблокирован. Для разрешения действий одновременно задайте `RTS_ALLOW_WRITES=true` и передайте `confirm=true` в конкретном вызове. Не используйте `rts_act` для ввода пароля, одноразового кода или PIN сертификата — вводите их вручную в браузере. Подписание ЭП, CAPTCHA и финальную отправку предложения должен подтверждать человек.

У площадки не найден опубликованный официальный API для этого регионального раздела, а публичный URL защищён Anti‑DDoS. Поэтому DOM-адаптер намеренно эвристический: после изменений интерфейса сначала вызовите `rts_open`, затем уточните селекторы. Для гарантированного промышленного обмена запросите у РТС‑тендер договорной API/интеграционный регламент и замените браузерный адаптер официальным клиентом.

## Telegram-бот оператора и участника

Бот расположен в `src/interfaces/telegram` и использует MCP-мост как единственный канал доступа к площадке. Он поддерживает поиск, карточки, AI-анализ, две рабочие роли, избранное, поисковые подписки и периодические уведомления.

1. Создайте бота через BotFather и узнайте свой numeric Telegram ID.
2. Скопируйте параметры из `.env.example` в окружение. Обязательно задайте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_ALLOWED_USERS`.
3. Для AI-анализа задайте `OPENAI_API_KEY`; без него доступен локальный базовый разбор дат и сумм.
4. Соберите и запустите:

```powershell
pnpm run build
pnpm run bot
```

### Расширенные фильтры

Фильтры поддерживают:

- обязательные и исключающие ключевые слова;
- минимальную и максимальную цену;
- заказчика, регион/место поставки и статус;
- один или несколько кодов ОКПД2, включая поиск по префиксу;
- диапазон оставшихся дней и календарные границы срока;
- наличие документации;
- сортировку по релевантности, цене, сроку или дате публикации.

Пример создания профиля:

```text
/filter Компьютеры | ключи=ноутбук, компьютер; исключить=ремонт, б/у; минцена=100000; максцена=3000000; регион=Краснодар; окпд=26.20; дней=3-30; документы=да; сорт=срок
```

После этого:

```text
/filters                       — открыть и запустить профили
/watchfilter <ID>              — включить мониторинг по профилю
/digest                        — получить сводку по всем профилям
/deadlines 14                  — сроки на ближайшие 14 дней
```

### Рабочая воронка

Стадии: `new`, `review`, `decision`, `prepare`, `submitted`, `won`, `lost`, `archived`.

```text
/stage review https://... первичная проверка ТЗ
/queue
```

Мониторинг сохраняет отпечаток каждой закупки и уведомляет отдельно о новых результатах и об изменениях уже известных карточек.

Полный перечень команд: `/search`, `/filter`, `/filters`, `/deadlines`, `/digest`, `/card`, `/analyze`, `/watch`, `/watchfilter`, `/queue`, `/stage`, `/favorites`, `/session`, `/role`, `/help`.

## Telegram Mini App

Встроенный мобильный кабинет находится в `public/miniapp` и работает через тот же MCP-мост и то же хранилище, что Telegram-бот. Он включает:

- обзор воронки, избранного и мониторингов;
- расширенный поиск с ценой, заказчиком, статусом, регионом, ОКПД2, ключевыми и исключающими словами, сроком и наличием документов;
- применение фильтров непосредственно в нативной форме РТС;
- сохранённые профили фильтров и создание/управление мониторингами;
- досье, готовность, план работ, отслеживание изменений и сравнение закупок;
- извлечение таблиц, пакетную загрузку документов и предпросмотр предложения;
- расчёт экономики участия, стадии рабочей воронки и диагностику авторизованного кабинета.

Mini App не требует купленного домена: после Railway Deploy используйте выданный Railway HTTPS-домен. Задайте его и в переменной, и в BotFather:

```text
MINIAPP_URL=https://ваш-сервис.up.railway.app
MINIAPP_DEV_BYPASS=false
TELEGRAM_AUTH_MAX_AGE_SECONDS=86400
RTS_ACCOUNT_OWNER_ID=123456789
RTS_ACCOUNT_OWNER_IDS=123456789,987654321
RTS_ALLOW_CLOUD_ACCOUNT_SESSION=false
```

В BotFather откройте `/mybots` → бот → **Bot Settings** → **Menu Button** и укажите тот же URL. Сервер проверяет криптографическую подпись `initData`, срок сессии и `TELEGRAM_ALLOWED_USERS` при каждом API-вызове.

Перед открытием рабочего кабинета Mini App показывает защищённое меню подключения. Оно не содержит полей логина, пароля, CAPTCHA, SMS-кода или PIN ЭП. Вход выполняется вручную только в отдельном Chromium на доверенном компьютере. `RTS_ACCOUNT_OWNER_IDS` задаёт владельцев независимых профилей через запятую: каждый Telegram ID сопрягает собственный компьютер и получает только свою сессию РТС. Для совместимости один основной профиль можно задать через `RTS_ACCOUNT_OWNER_ID`. Если `TELEGRAM_ALLOWED_USERS` содержит ровно один ID, он становится владельцем автоматически.

Облачная авторизация аккаунта по умолчанию заблокирована. Не включайте `RTS_ALLOW_CLOUD_ACCOUNT_SESSION` в Railway: cookies кабинета и локальная ЭП должны оставаться на рабочем компьютере. Для защищённой работы запускайте Mini App и MCP-мост локально с `RTS_HEADLESS=false`, а Telegram подключайте к локальному HTTPS-сервису через доверенный частный туннель. Администратор сервера всё равно контролирует исполняемый процесс, поэтому абсолютную защиту от скомпрометированного хоста программно гарантировать невозможно.

Локально интерфейс можно запускать отдельно от бота:

```powershell
$env:MINIAPP_DEV_BYPASS="true"
$env:MINIAPP_PORT="3000"
pnpm run build
pnpm run start:web
```

Обход авторизации действует только для loopback-адреса и не должен включаться в Railway.

### Глубокая интеграция с кабинетом РТС

После ручного входа в постоянном Chromium-профиле мост умеет инвентаризировать фактический интерфейс аккаунта. Он распознаёт поиск, фильтры, карточки, документы, ценовые предложения, заявки, договоры, разъяснения, протоколы и профиль организации по видимым элементам страницы.

```text
/workspace
/sitefilter запрос=ноутбук; заказчик=Администрация; минцена=100000; максцена=3000000; окпд=26.20; регион=Краснодар
/documents https://krd-market.rts-tender.ru/...
/tables https://krd-market.rts-tender.ru/...
/dossier https://krd-market.rts-tender.ru/...
/track https://krd-market.rts-tender.ru/...
/compare URL1 URL2
/draft URL | цена=125000; количество=10; поставка=7; срок=30; комментарий=текст
/readiness URL
/economics цена=1000000; себестоимость=650000; логистика=50000; накладные=30000; налог=6; резерв=5; прибыль=12
/workplan URL
```

Адаптивная инвентаризация не заменяет контрактный API, но позволяет подключать разные роли и версии интерфейса без хранения паролей и без жёсткой зависимости от одного CSS-класса.

Досье включает нормализованные условия, контроль полноты, документы, таблицы, доступные действия и SHA‑256-отпечаток. Повторный `/track` выделяет изменения цены, срока, статуса, заказчика, места поставки и состава документов. `/draft` в Telegram работает только как предпросмотр; MCP может заполнить поля при явном разрешении записи, но никогда не нажимает отправку, публикацию или подписание.

Бот намеренно не принимает пароль, CAPTCHA, PIN электронной подписи и не выполняет финальное подписание/отправку. Эти действия остаются в локальном браузере и требуют человека. Перечень функций площадки, доступных только после входа конкретной организации, можно окончательно картировать после ручной авторизации в постоянном профиле.

## Что требуется для промышленной эксплуатации

- отдельный системный пользователь и закрытая папка для Chromium-профиля;
- резервное копирование `.bot-data` и `.rts-device` и контроль прав доступа (в `.rts-device` лежит токен доступа локального агента);
- заданный и отдельно сохранённый `DATA_ENCRYPTION_KEY` для шифрования `.bot-data` (см. «Шифрование локального хранилища»);
- supervisor/service для перезапуска процесса и для `pnpm run local-agent`, если используется режим `RTS_TRANSPORT=hub`;
- ручное тестирование после каждого изменения интерфейса РТС;
- согласованный с РТС-тендер официальный API, если он доступен по договору;
- журналирование юридически значимых действий и правило «четырёх глаз» для подачи/подписания;
- отдельный тестовый контур до включения `RTS_ALLOW_WRITES=true`.

## Развёртывание на Railway

В репозитории есть `railway.json`: Railway собирает TypeScript и запускает единый процесс командой `pnpm run start:app`. Он поднимает HTTPS Mini App/API на порту из `PORT`, Telegram-бота и дочерний MCP-мост.

Обязательные переменные Railway:

```text
TELEGRAM_BOT_TOKEN=...
TELEGRAM_ALLOWED_USERS=123456789
TELEGRAM_ADMIN_USERS=123456789
MINIAPP_URL=https://ваш-сервис.up.railway.app
MINIAPP_DEV_BYPASS=false
RTS_HEADLESS=true
RAILPACK_NODE_PLAYWRIGHT_INSTALL=1
```

Рекомендуемые переменные при подключённом Railway Volume в `/data`:

```text
BOT_DATA_DIR=/data/bot
RTS_PROFILE_DIR=/data/rts-profile
RTS_DOWNLOAD_DIR=/data/downloads
RTS_SNAPSHOT_DIR=/data/snapshots
OPENAI_API_KEY=...
OPENAI_MODEL=gpt-5.4
AI_ANALYSIS_ENABLED=false
```

`pnpm-workspace.yaml` обязательно содержит `packages: ["."]`; без этого pnpm 9 в Railpack завершает установку ошибкой `packages field missing or empty`.

Railway запускает `pnpm run build:railway`, который дополнительно устанавливает полный Chromium. Одного `RAILPACK_NODE_PLAYWRIGHT_INSTALL=1` недостаточно для `launchPersistentContext`: Railpack устанавливает только облегчённый headless-shell.

Если RTS сбрасывает соединение с IP Railway (`ERR_CONNECTION_RESET`), задайте в Railway переменную `RTS_PROXY_SERVER` (например, `http://host:port`). Для прокси с авторизацией также задайте `RTS_PROXY_USERNAME` и `RTS_PROXY_PASSWORD`. Используйте доверенный статический IP: через браузерный профиль проходят данные аккаунта и электронной подписи. Число повторов навигации регулирует `RTS_NAVIGATION_RETRIES` (по умолчанию `3`).

Важно: площадка использует Anti-DDoS и ручную авторизацию/ЭП. Обычный headless Chromium в Railway может не пройти защиту. Раздел ниже описывает штатный способ совместить облачный Mini App/бота на Railway с браузером, который физически остаётся на компьютере владельца.

## Локальный агент: защищённая связь Railway ↔ компьютер

По умолчанию (`RTS_TRANSPORT=local`) MCP-мост запускается как дочерний процесс того же приложения — это подходит для одной машины, но означает, что на Railway Chromium с авторизованным профилем должен был бы работать в облаке (`RTS_ALLOW_CLOUD_ACCOUNT_SESSION=true`), чего мы избегаем по умолчанию.

Вместо этого Railway может держать только Mini App и бота, а браузер РТС — работать на компьютере владельца и подключаться к Railway самостоятельно, исходящим защищённым WebSocket-соединением. Открывать входящий порт на компьютере не нужно.

```text
Telegram Mini App → Railway (Mini App API + бот) ⇄ WSS ⇄ локальный агент → Chromium → РТС-Маркет
```

На Railway:

```text
RTS_TRANSPORT=hub
```

На компьютере владельца (тот же `.env`, что и для локального MCP-моста):

```text
AGENT_HUB_URL=https://ваш-сервис.up.railway.app
RTS_DEVICE_DIR=.rts-device
RTS_HEADLESS=false
```

Сопряжение выполняется один раз:

1. В Mini App: **Подключение → «Подключить компьютер»** — сервер выдаёт одноразовый код (действует несколько минут, привязан к Telegram ID владельца).
2. На компьютере: `pnpm run build && pnpm run pair-device <код>`. Скрипт создаёт идентификатор устройства в `RTS_DEVICE_DIR` и получает токен доступа — он хранится только локально с правами `0600` и никогда не показывается повторно.

Удалённый `AGENT_HUB_URL` обязан использовать `https://` (WebSocket автоматически станет `wss://`). Незашифрованные `http://` и `ws://` разрешены только для loopback-адресов при локальной разработке. URL со встроенным логином или паролем отклоняется.
3. Запуск агента: `pnpm run local-agent`. Он подключается к Railway, проходит аутентификацию токеном устройства и ждёт команд. Дальше в открывшемся Chromium вручную пройдите Anti‑DDoS и вход, как обычно.

Если Anti-DDoS зацикливается в окне, запущенном Playwright, используйте подключение к обычному локальному Chrome без переноса cookies из личного профиля:

```bash
pnpm run open-connected-chrome
```

Пройдите проверку и вход вручную в этом видимом окне, затем запустите агент с `RTS_CDP_URL=http://127.0.0.1:9222`. Мост подключится к уже открытому Chrome и не создаст второе окно. Порт принимается только на loopback-адресе; удалённый CDP запрещён.

Свойства канала:

- пароль, PIN сертификата, cookies и содержимое профиля Chromium по каналу никогда не передаются — только результат вызова инструментов РТС‑моста;
- абсолютные локальные пути, stack trace и необработанные тексты ошибок агента удаляются до отправки в облачный мост;

Важно: результаты поиска, досье и аналитики передаются через Railway по TLS, потому что облачный бот должен вернуть их Mini App. Это не zero-knowledge/E2EE-модель: процесс сервиса технически обрабатывает эти результаты. Учётные данные, cookies, профиль Chromium, локальные пути и ключи ЭП при этом остаются на компьютере. Для закупок, содержимое которых запрещено обрабатывать в облаке внутренней политикой организации, используйте полностью локальный режим `RTS_TRANSPORT=local`.
- агент выполняет только методы из явного списка разрешённых (`rts_search_advanced`, `rts_get_request`, `rts_build_dossier` и т.п.); `rts_act` и произвольная загрузка по URL через канал недоступны — только локально;
- у каждого RPC-запроса есть таймаут, ограничение размера ответа и защита от повторного воспроизведения (id + отметка времени);
- один Telegram-владелец — один активный агент; новое подключение вытесняет предыдущее;
- несколько владельцев работают параллельно: команды моста, устройства, фильтры, мониторинги и данные Mini App изолированы по Telegram ID;
- устройство можно отозвать в любой момент — командой `/devices` в боте или в Mini App; отозванное устройство не проходит аутентификацию и немедленно отключается, если было в сети;
- `/connection`, `/devices`, `/disconnect`, `/security` в боте показывают состояние подключения без раскрытия секретов.

Ограничение текущей реализации: реестр подключённых агентов живёт в памяти процесса, поэтому в режиме `RTS_TRANSPORT=hub` Mini App и бот должны работать в одном процессе — используйте `pnpm run start:app` (как в `railway.json`), а не раздельные `start:web`/`start:bot` как отдельные сервисы.

`pnpm run local-agent` не завершает работу сам — держите его запущенным (как службу/автозагрузку) на компьютере владельца, пока нужен удалённый доступ через Railway.

## Надёжность браузерных операций

Все MCP-инструменты работают с одной и той же страницей Playwright, поэтому:

- каждый вызов инструмента проходит через общую очередь (`infrastructure/rts/operation-queue.ts`): операции выполняются строго по одной, даже если два вызова (например, команда в Telegram и сработавший мониторинг) пришли одновременно;
- у каждого вызова есть таймаут ожидания в очереди (`RTS_QUEUE_TIMEOUT_MS`, по умолчанию 120 с) — вызывающая сторона не ждёт бесконечно, но сама операция не прерывается и очередь всё равно дожидается её реального завершения, чтобы не открыть доступ к странице второй операции раньше времени;
- при заведомо зависшем действии Playwright восстанавливается за счёт собственного таймаута `RTS_TIMEOUT_MS` — принудительного перезапуска браузера очередь не выполняет;
- навигация к РТС классифицируется на сетевую ошибку, таймаут и общую ошибку навигации (`infrastructure/rts/errors.ts`), а пользователю всегда возвращается короткое стабильное описание на русском, без сырого текста Playwright или внутренних URL;
- после нескольких подряд неудачных попыток навигации (`RTS_CIRCUIT_THRESHOLD`, по умолчанию 5) включается предохранитель: дальнейшие вызовы сразу отклоняются на время `RTS_CIRCUIT_COOLDOWN_MS`, вместо повторного давления на недоступную площадку;
- MCP-клиент (`application/mcp-client.ts`) переиспользует один дочерний процесс, безопасно обрабатывает параллельный первый вызов (не плодит вторые подпроцессы) и автоматически переподключается, если MCP-процесс или Chromium неожиданно завершились — следующий вызов просто поднимет их заново.

## Шифрование локального хранилища

`BOT_DATA_DIR` (фильтры, мониторинги, воронка, избранное, привязки устройств) можно шифровать на диске AES-256-GCM. По умолчанию (`DATA_ENCRYPTION_KEY` не задан) файлы остаются в прежнем читаемом JSON — поведение не меняется для тех, кто не настраивал ключ.

```text
DATA_ENCRYPTION_KEY=<64 hex-символа или base64 32 байт>
```

Как только ключ задан:

- каждая запись шифруется отдельным случайным IV и снабжена authentication tag (GCM), формат версионирован;
- запись по-прежнему атомарна (запись во временный файл и `rename`);
- уже существующий незашифрованный `bot.json`/`devices.json` при первой записи прозрачно мигрирует в зашифрованный формат, а рядом сохраняется зашифрованная резервная копия исходного файла — `<файл>.bak-<timestamp>.enc`;
- чтение зашифрованного файла без ключа или с неверным ключом завершается понятной ошибкой («неверный DATA_ENCRYPTION_KEY или повреждённые данные»/«DATA_ENCRYPTION_KEY не задан») — без утечки самого ключа и без молчаливой потери данных.
- резервная копия при первой миграции также создаётся в AES-256-GCM envelope; обнаруженные старые plaintext-backup-файлы автоматически шифруются при следующей записи.

Удаление постоянного профиля по умолчанию заблокировано. Для аварийного сброса на локальном агенте временно задайте `RTS_ALLOW_PROFILE_DELETION=true`; операция дополнительно требует точную фразу подтверждения и действительный служебный маркер внутри отдельного каталога профиля. Корневой каталог диска, домашняя папка и корень проекта удалить через мост невозможно.

Не используйте `TELEGRAM_BOT_TOKEN` как ключ шифрования: при его ротации (например, при компрометации бота) старые зашифрованные данные станут нечитаемыми. Храните `DATA_ENCRYPTION_KEY` отдельно от `BOT_DATA_DIR` и от `.env`, который попадает в резервные копии контейнера.
